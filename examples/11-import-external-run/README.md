# Import a run from a project that does not use CairnML

## Goals

Bring a training run made without CairnML into the web app, by rearranging its files into the import format.

What you will learn:

- What an import expects: a folder with a manifest, the settings, the per-epoch scalars and the checkpoints.
- How a small adapter maps one project's names to CairnML's names.
- How to package a run with `cairnml import prepare` and upload it in the web app.

## Background

Results often exist before CairnML does: old experiments, or a project you cannot or do not want to change. Importing them puts old and new runs in one place, where they can be compared like native runs.

The "legacy" project here is a plain training script that writes its own files for each run:

```
runs/greenhouse_mlp_20261101_120000/
    settings.txt       the settings, one "name = value" per line
    log.csv            one row per epoch: Epoch, Train Loss, Val Loss, Val R2
    model_final.pth    the weights after the last epoch
    model_best.pth     the weights of the epoch with the lowest validation loss
```

These names belong to that project, and CairnML cannot read them as they are. The adapter you run reads the folder, changes nothing in it, and writes the layout CairnML imports:

| Legacy file or column | CairnML name | Result in the web app |
|---|---|---|
| `settings.txt` | `args.yaml` | parameters in the task's **Args** |
| `log.csv`, `Epoch` | `epoch` | the step of every scalar |
| `log.csv`, `Train Loss` and `Val Loss` | `loss/train` and `loss/val` | the scalar **loss**, series **train** and **val** |
| `log.csv`, `Val R2` | `r2/val` | the scalar **r2**, series **val** |
| `model_final.pth`, `model_best.pth` | `weights/` | model artifacts |

`Val R2` is the regression counterpart of accuracy: 1.0 is a perfect fit and 0 is no better than predicting the average.

## Prerequisites

- About 10 minutes.
- [Example 6](../06-regression-dataset) done. Its repository URL and commit are passed as `--repo` and `--commit`.
- The [SDK connected to your server](../00-installation-and-setup). Building the ZIP does not need the server, but reading the dataset and the upload do.

## Steps

### 1. Install

```bash
cd ~/cairnml-examples/examples/11-import-external-run
source ~/cairnml-examples/.venv/bin/activate
pip install -r requirements.txt
```

In every new terminal, run `source ~/cairnml-examples/.venv/bin/activate` again before you run the example.

### 2. Run the legacy training

```bash
cd legacy_project
python train_legacy.py --repo https://github.com/<your-user>/greenhouse-data.git --commit <sha> --epochs 30
cd ..
```

The script trains on the greenhouse data of that dataset version and prints the folder it wrote, for example `runs/greenhouse_mlp_20261101_120000`, and the best validation loss and final R². It does not use CairnML, so nothing is recorded on the server yet.

### 3. Export the run

```bash
python export_to_cairnml.py legacy_project/runs/greenhouse_mlp_20261101_120000 --project examples
```

The adapter renames the columns as in the table above, copies the results into a scratch folder in the import layout together with a copy of the training script, runs `cairnml import prepare` to pack it with a manifest, and writes the ZIP to `exports/`. Pass `--task "greenhouse MLP (legacy)"` to choose the task name.

Look inside:

```bash
unzip -l exports/greenhouse_mlp_20261101_120000.zip
```

It holds `cairnml-import.yaml` (the manifest, with the project and task name), `args.yaml`, `results.csv` with one row per epoch, and `weights/` with both checkpoints.

### 4. Import it in the web app

1. Choose **Import run** and upload the ZIP.
2. Open the new task in the project **examples**: the settings are under **Configuration**, the three curves under **Scalars**, and the checkpoints under **Artifacts**.

Each import creates a new task, so importing the same ZIP twice gives two tasks.

Compare the imported task with the baseline of [Example 8](../08-hyperparameter-optimisation): same data, a different network and training loop, so the validation curves should land in the same range. The `r2/val` curve approaches 1.0 but does not reach it, because of the noise in the data.

## Troubleshooting

- **`missing columns`:** the legacy log lacks one of the four columns. Change the names in `COLUMNS` in `export_to_cairnml.py`.
- **`project is empty`:** add `--project examples`, which the importer requires.
- **`no weights/ folder`:** the run has no checkpoints, so no model is imported. The scalars still import.
